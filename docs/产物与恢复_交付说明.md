## 3. 关键设计决定

**确认前下游不可消费**：节点只有在两步提交确认后才进入 `succeeded`；第四阶段的暂存成功（`staged_only`）路径被第五阶段的两步提交取代——半成品永远留在暂存区，不会成为正式结果（9.5 通过标准第 3 条）。

**持久依赖只登记在正式结果上**：`keep_forever`（正式 LST/填洞/最佳模型）发布时登记运行级 pinned 引用，即使无进程读取也不删除；可重建中间产物按「无活动使用 + 保留策略」清理，历史节点成功与文件当前可取是两个独立属性（§10.3）。

**runs 目录布局**：`<executions>/runs/<run_id>/committed/<node_key>/attempt-N/`，由后端生成、永不覆盖；尝试暂存 `<executions>/runs/<run_id>/staging/<attempt_id>/work`（沿用第四阶段布局，§10.1）。

**恢复不扩大输出清单**（§8.4/§11.2）：重启后已登记 prepared 意向的尝试复用既有意向与输出清单继续发布/确认；暂存不完整且未发布的按对账政策标失败。
