# 功能与使用指南

## 一、系统特色与重要功能

### 3.1 面向连续任务的记忆系统

　　GeoThermoAI 不把每次对话视为彼此孤立的请求。系统以项目和对话为边界保存已确认的研究区、时间条件、用户偏好、执行方案和实验结果，使用户再次进入同一项目时能够继续已有任务，而不必重复说明全部背景。

　　记忆内容分为三个层次。对话记忆保存当前任务意图、已确认条件、待补充信息和用户批准状态。项目记忆积累历史实验、结果指标、数据组合和可复用流程。领域记忆提供地表温度、遥感数据质量、模型训练与结果评价相关知识。系统根据当前角色检索不同内容，例如 Data 角色优先关注数据与质量控制，Train 角色优先参考模型经验，Evaluation 角色优先调用评价知识。只有通过评价的成功流程才会进入可复用经验，使后续任务能够借鉴历史结果，同时保留用户重新选择参数和数据的权利。

　　GeoThermoAI 采用**精确查询 + RAG 语义检索双轨制**：写入时双写（JSON 结构化记录 + ChromaDB 向量段落），读取时四段叠加注入 prompt——领域知识 RAG、项目经验 RAG、历史最佳实验（按 R² 精确排序）、以及从用户 query 正则提取 region/时间/影像对日期后的结构化精确匹配。RAG 用 bge-small-zh-v1.5 ONNX 嵌入 + cosine 相似度负责"语义相关"，JSON 精确查询负责"指标可溯源"，两者按角色（planner/data/train/eval）定制检索范围和条数，RAG 失败时有多级兜底（无过滤查询 → 精选种子条目）。核心思路是**语义检索找相关、精确查询对指标**，避免单纯 RAG 在需要精确字段匹配的场景下不命中。

### 3.3 Chat 与 Work 双模式可选

　　此功能的设计灵感来源于 ChatGPT 桌面端当前的“聊天”“工作”双模式以及 Qoder Desktop 编辑器模式下的“智能问答”“智能体”双模式，旨在为不同对话任务划定执行边界，确保任务针对性与可控性。

#### 3.3.1 Chat 模式

　　Chat 用于解释算法、参数、指标和结果边界。它不会启动数据下载或修改结果，适合用户在运行前了解方法，在运行后询问温度值和精度含义。

#### 3.3.2 Work 模式

　　Work 用于执行完整任务。系统先形成方案，再依次完成数据获取、预处理、地形热响应计算、模型训练、热约束校正、产品导出和精度评价。界面同步展示当前阶段、运行状态和结果入口。

### 3.4 “由我批准”与“完全执行”双模式可选

　　此功能设计的设计灵感来源于 ChatGPT 桌面端的“请求批准”“帮我批准”“完全访问”三种模式。“由我批准”与“完全执行”双模式是面向工作流处理的，因而仅在 Work 模式下可选。

#### 3.4.1 由我批准模式

　　“由我批准”适合希望控制过程的用户。系统会在方案确认和关键选择处暂停（如影像配对的选择、超参数寻优等节点），用户可以接受推荐，也可以调整研究区、时间、数据组合或模型参数。

#### 3.4.2 完全执行模式

　　“完全执行”适合参数已经明确的任务。系统按照既定规则连续完成各阶段（包括自动选择并下载最合适的影像与 LLM + 规则约束的智能调优等），如果数据不完整或质量不足时会自动停止，不以占位影像替代缺失数据。完全执行与由我批准模式模式共享相同的遥感处理与评价标准，区别只在于人工介入程度，完全执行模式在确定了执行任务安排后无需人工干预，因此完全执行模式也更适合不了解使用原理的新手用户。

### 3.6 支持配对模式与月度合成模式两种处理模式

　　GeoThermoAI 使用的降尺度策略依赖 Sentinel-2 影像为 Landsat 地表温度数据提供空间细节，因此需要这两种卫星的影像形成配对，过境时间差小于等于 2 天且天气情况相似形成的真配对与月度合成影像形成的伪配对均可。因此 GeoThermoAI 提供面向真实精确地表热场景的配对模式和面向长时序月度地表热环境监测的配对模式，用户可以直接将配对模式或月度合成模式的要求包含在指令（用户提示词）中，由 GeoThermoAI 智能解析，当用户没有准确说明时，GeoThermoAI 将主动向用户提问。

　　GeoThermoAI 采样的月度合成算法为遥感领域常用的中值合成算法。

　　为了保障数据检索与下载的便捷性，同时考虑到国内直连 GEE 的不便性以及 GEE 下载数据的复杂繁琐流程，GeoThermoAI 使用了两个数据获取来源的数据，分别是 Microsoft Planetary Computer 和 Copernicus Data Space，获取前述三种数据的 COG 影像并进行处理。GeoThermoAI 默认使用 Microsoft Planetary Computer 搜索下载 Landsat 数据，默认优先使用 Copernicus Data Space 搜索下载 Sentinel 数据与 DEM 数据，兜底回退到 Microsoft Planetary Computer。

## 二、快速上手与在线体验

　　我们在魔搭创空间 ModelScope Studio 中部署了在线可交互应用便于使用者探索 GeoThermoAI 的能力。但需要说明的是：

1. 由于 ModelScope Studio 的实例并没有针对不同用户进行隔离，因此我们设计了一套用户登录系统，您需要填写账号名、昵称、密码等信息完成注册登录，我们不会收集您的任何个人隐私，用户登录系统仅为了隔离不同用户在 ModelScope Studio 上使用 GeoThermoAI 产生的数据；
2. ModelScope Studio 上的云资源有限（我们使用的是免费CPU、按需分配2v CPU、16G内存配置），多用户同时进行操作时可能导致超过云资源的内存和磁盘上限导致崩溃；因此如果您需要进行严肃的使用（如生成武汉市的 10m 地表温度产品），我们推荐您在本地的 Docker 中进行部署，拉取本仓库进行本地部署，即使您不会使用 Docker 也没关系，AI 时代您可以将 Docker 部署此种繁琐任务交给 AI 。

### 4.0 本地 Docker 部署

　　容器内的 `/app/data` 是账号、对话、研究区、任务台账、记忆和默认项目数据的持久根。生产运行必须挂载该目录，否则删除容器时会一并删除运行状态。下面的命令使用 Docker 命名卷，重建容器后仍可恢复原任务与记忆：

```bash
docker build -t geothermoai-image .
docker volume create geothermoai_data
docker run -d --name geothermoai -p 7860:7860 \
  --memory=16g --cpus=16 \
  -v geothermoai_data:/app/data \
  geothermoai-image
```

　　若项目影像需要放在另一块大容量盘，可另设 `WORKSPACE_ROOT` 并挂载对应目录；SQLite 仍应留在单机本地持久盘。并发数、下载连接、CPU、内存、磁盘缓存、超时、记忆写回重试和缓存上限均可通过 `config/deployment.json` 或环境变量配置。非法数值、不可写目录和 SQLite 网络盘会使服务明确拒绝启动。完整变量表和迁移说明见 [部署配置说明_第七阶段](部署配置说明_第七阶段.md)。

### 4.1 基础配置

　　本小节介绍在正式使用 GeoThermoAI 生成 10m 地表温度产品之前需要完成的各项配置，包括 LLM 配置、数据源配置、连接测试、研究区配置与模型初始参数配置。这些配置均在进入对话后打开工作面板完成。工作面板由「API设置」「数据源」「测试」「研究区」「初始参数」「下载」「地图」「进度」「日志」「最终精度」等子页面组成，其中前五项为使用前需要确认的配置项，后五项用于查看任务进度与处理结果。

#### 4.1.1 LLM API 配置

　　进入 GeoThermoAI 页面后，打开工作面板并切换到「API设置」页面。首先选择 API 格式，系统支持 OpenAI Chat Completions 格式与 Anthropic Messages 格式，需根据所选模型厂商选择对应的兼容格式；然后在「请求地址」中填写模型的 Base URL（例如 [https://api.deepseek.com](https://api.deepseek.com)），系统会自动在末尾补全对应的接口路径；接着填写「模型 ID」与「API 密钥」。在「高级配置」中还可以设置「模型展示名称」与「上下文窗口」（上下文-输入、上下文-输出），上下文窗口应按所选模型的支持范围填写。相关配置方法可前往各模型厂商的开发平台查询。配置完成后点击「保存并应用」，模型即热更新生效。出于安全考虑，已保存的密钥不会以明文回显，而是显示为黑点占位；需要更换时重新输入即可覆盖原值。

　　我们推荐使用 DeepSeek V4 Flash，其最新的正式版已接入 API 且成本低廉能力强，性价比高。

#### 4.1.2 数据源配置

　　数据获取环节不需要用户手动上传原始影像，系统会自动从 Microsoft Planetary Computer 与 Copernicus Data Space 两个数据源检索并下载所需数据，具体分工为：Sentinel-2 L2A（多光谱与场景分类）优先使用 Copernicus Data Space，失败时自动回退 Microsoft Planetary Computer；Landsat 8/9 L2（地表温度与质量标识）使用 Microsoft Planetary Computer；DEM（Copernicus GLO-30）优先使用 Copernicus Data Space，需配置 S3 密钥，否则使用 Microsoft Planetary Computer。

　　考虑到国内直连国外数据服务的不便，建议在「数据源」页面填写 Copernicus Data Space 的注册账号与密码（在 dataspace.copernicus.eu 注册），以便优先使用国内访问更快的 Copernicus Data Space。在「高级配置」中还可填写 OAuth2 Client ID 与 Client Secret（用于影像搜索）以及 S3 Access Key 与 S3 Secret Key（DEM 走 Copernicus Data Space 下载时必需）。未配置或下载失败时，系统会自动回退 Microsoft Planetary Computer，不影响基本使用。

　　如果感觉 Copernicus Data Space 配置太复杂也没有关系，可以什么数据源都不配置，系统将自动回退到 Microsoft Planetary Computer 进行检索与下载，代价是国内虽可直连但比 Copernicus Data Space 下载更慢。

　　另外，无论采用何种数据源，我们都建议在本地 Docker 部署 GeoThermoAI 时开启代理达到更快的下载速度。

#### 4.1.3 连接测试

　　完成上述配置后，可以在「测试」页面逐一验证各项配置是否生效。该页面提供三项测试：测试 Planetary Computer 连接、测试 Copernicus Data Space 连接与测试地理处理环境。测试结果以状态行的形式展示，通过、警告与失败分别以不同颜色标识。若某项数据源连接失败，可据此判断是网络问题还是凭据配置问题，并在「数据源」页面修正后重新测试。

#### 4.1.4 研究区配置

　　研究区范围是数据获取与全流程执行的必需输入。在「研究区」页面点击上传按钮，选择 GeoJSON 或 Shapefile 文件（.geojson/.json/.shp/.dbf/.shx/.prj）即可上传研究区；多个研究区可以同时保存，点击列表中的条目即可切换当前使用的研究区，点击删除按钮可移除不再使用的研究区。Agent 在执行数据获取与全流程任务时会以当前研究区为准。

#### 4.1.5 模型初始参数配置

　　模型训练使用 Random Forest 回归，机器学习方法暂时固定不可修改。在「初始参数」页面可以通过滑动条调整四个超参数：n\_estimators（决策树数量）、max\_depth（最大深度）、min\_samples\_split（内部节点再划分所需最小样本数）与 min\_samples\_leaf（叶节点最小样本数），系统提供了各参数的推荐取值范围。对于大多数任务，保持默认参数即可获得可靠结果；如需调整，也可以在「由我批准」模式的方案确认节点按需修改。

　　GeoThermoAI 被设计为项目制管理模式，可以创建多个项目，每个项目内可以创建多个对话，项目之间的记忆是隔离的，而项目内部的记忆是共享的。建议的使用方式为一个项目用于一个地区的地表温度产品生成。

### 4.4 提交研究任务

#### 4.4.1 设置研究条件

　　在研究区面板中上传并选择研究区。随后用一句完整的话说明目标，例如“对武汉市开展 2024 年 7 月地表温度降尺度”。若采用“由我批准”，系统会先列出研究区、时间条件、候选数据和处理阶段，用户确认后再进入计算。

#### 4.4.2 查看运行状态

　　任务开始后，工作台按阶段显示数据获取、预处理、地形热响应、模型训练、热约束校正、产品导出和精度评价的状态。若数据缺失或质量检查不通过，流程会在对应阶段停止并说明原因，不会用占位影像继续生成结果。

### 4.5 查看地图与精度

#### 4.5.1 查询像元温度

　　一旦有地表温度图层生成，包括下载的 30m 的 Landsat 地表温度，就可以在地图中选择地表温度图层并开启温度查询。温度显示面板的各图层温度以及坐标信息会随鼠标光标移动而变化，单击某一像元后，界面将锁定当前坐标与开尔文温度，直至再次点击自动解锁。图层选择、透明度调整和像元查询可参考之前章节的图 1 和图 2。

#### 4.5.2 阅读精度指标

　　精度面板汇总空间分块留出测试的 $R^2$ 、 $RMSE$ 、 $MAE$ 和 $MB$ ，并给出样本数与温度值域。图 7 展示了最终精度面板。阅读时应把测试区精度理解为 30m 标签上的模型评价，而不是独立 10m 真值误差。面板集中展示测试集评价指标、样本数量和有效温度范围，便于用户判断结果的适用边界。

### 4.6 数据与结果下载

　　GeoThermoAI 会保存下载的原始数据、算法中间过程文件已经最终结果，可在工作面板的下载面板中进行下载，其中 raw 子目录下即为原始数据，result 子目录下有生成的地表温度产品。您可以下载数据后在 ENVI、ArcGIS Pro、QGIS 等软件中进行后续分析。
