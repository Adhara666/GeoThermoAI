## 2. 第七阶段开始前确认的缺口

1. 第一阶段已经预留 `projection_jobs` 表，第五阶段也会登记 `run_manifest_view` 待办，但没有后台消费者；新调度链成功后不会可靠写回实验或成功工作流。
2. 旧执行器中的记忆写入直接在流程尾部调用，JSON 与 Chroma 失败会被各自吞掉，无法恢复、有限重试或查明状态；随机工作流编号也不能保证幂等。
3. 每个用户都会独立加载一份嵌入模型，Assistant、Agent 和记忆管理器缓存均为无上限字典。Data Space 搜索缓存虽在读取时判断十分钟，但过期条目没有真实删除，也没有容量上限。
4. `WORKSPACE_ROOT` 同时被当作项目盘和部分账号目录使用，账号注册表、JWT、对话、记忆与 SQLite 仍有仓库 `data` 硬编码。Dockerfile 没有完整表达持久根语义，也没有集中校验路径和预算配置。
5. 老对话 JSON 仍可由旧界面读取，但没有一次性、可审计的台账导入记录；老结果也没有“历史引用已核验但科学运行未知”的诚实状态。
6. 新版 ChromaDB 对集合名只接受 ASCII 安全字符，中文项目名会导致向量记忆写入失败。此前测试没有覆盖真实 Chroma 调用。

## 4. 第七阶段实施边界

本阶段只改变运行完成后的记忆投影、部署路径、资源配置、缓存生命周期和旧数据登记，不修改定标、掩膜、划分、TTRI、随机森林、TCR、导出或闭合评价算法。完成状态仍由 SQLite 运行与节点事实决定；记忆是可重建投影，写回失败不能反向覆盖科学结果。
