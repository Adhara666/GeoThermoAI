## 当前项目在做什么

GeoThermoAI 把用户的地区、日期和产品要求转为遥感数据检索与地表温度降尺度任务。FastAPI 的 `server.py` 提供鉴权、项目、聊天、地图与文件接口，`frontend/src` 是 Vue 界面。科学主链在 `core/pipeline.py`，依次执行预处理、空间块缓冲划分、固定训练集 TTRI、RF、预测集 TTRI、TCR、最终温度、GeoTIFF 与粗尺度闭合评价。`core/skills/builtin` 包装这些调用，数据获取还负责 STAC、配对、逐景定标和月度合成。

## 前三阶段的真实状态

| 层 | 已有实现 | 尚未接通的责任 |
|---|---|---|
| 状态内核 `core/state_kernel` | SQLite schema v2，单一写入线程，命令幂等，任务与问题版本，关键事件 | attempts 等表仍主要是骨架，尚无实际资源预留与工作进程 |
| 理解层 `core/agent/understanding` | 候选解析，边界绑定，否定留痕，多任务，持久问题，Chat 禁止生产 | `server.py` 仍只把第一项就绪任务交给旧执行器 |
| 计划编译 `core/planning` | 冻结快照，15 节点生产图，能力校验，显式重建，替代运行记录 | 节点只排队不执行；替代运行创建路径尚未复制节点图，需要在执行接缝补齐 |
| 旧角色与执行器 | Planner、Data、Train、Eval，既有七规则调优和最佳轮逻辑 | 同步 Skill 调用，内存等待，按修改时间找模型，不能直接作为新调度器 |
| 结果和界面 | 原运行清单，地图、精度、下载，第二阶段任务快照 | 正式产物两步提交、恢复对账和完整任务界面分别属于阶段 5、6 |

发现编译事务保存的是更新前任务版本，而任务随编译递增版本。执行授权必须绑定编译后的有效版本，并兼顾仅改变状态或优先级时的版本语义。现有 planning 接口也需要补齐用户归属检查。

`server.py` 模块级导入算法、记忆与地图并创建 `AppBackend`，不能直接在此基础上启动 spawn。下载 `_fetch_asset` 累积所有字节块，`_fetch_asset_parallel` 分配整文件 bytearray；探测请求也未流式读取。以上均属于本阶段需要改造的执行边界。
