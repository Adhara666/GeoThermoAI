## 调度和传输验收

以下测试都使用真实 SQLite 台账和 `spawn` 工作进程，不替换成线程内假执行。

| 测试 | 结果 |
|---|---:|
| 状态内核回归 `tests/test_state_kernel.py` | 31/31 通过 |
| 理解层回归 `tests/test_understanding.py` | 100/100 通过 |
| 计划编译回归 `tests/test_planning.py` | 43/43 通过 |
| 调度专项 `tests/test_scheduling.py` | 8/8 通过 |
| 保护队列公平性 `tests/test_fairness.py` | 1/1 通过 |
| 传输专项 `tests/test_transfer.py` | 7/7 通过 |
| 常规测试集合 | 16/16 通过 |

调度专项覆盖计算与下载交错、网络节点有界重试、崩溃只阻塞自己的后继、取消期间资源不提前释放、持久审批问题、迟到授权丢弃、唯一调度器和实测内存压力。公平性测试观察到同优先级填洞节点连续两次有足够资源却被主产品节点跳过后进入保护队列并获得下一次机会。

传输专项覆盖 Range 区间和强 ETag 校验、忽略 Range 的顺序回退、错误区间拒绝、取消后的已验证分片续传、源版本变化使旧分片失效、未知长度的有界写盘，以及同一缓存项的操作系统单写者锁。

独立 2 GiB 流式探针得到完整文件，RSS 从 33.82 MiB 到 49.60 MiB，增加 15.78 MiB，没有把整个文件读入内存。

Web 生命周期在带完整依赖的容器内通过。轻量 `server.py` 可被 spawn 子进程导入，`AppBackend` 启动和关闭调度器成功，调度状态只返回当前用户的节点和资源预留。删除项目或对话前会先取消并等待该作用域的写入者退出。

## 边界和未提前实现的内容

执行输出仍是 staging 引用，尚未登记为正式产物；服务重启后对完整完成描述的受限接管只保留在调度器边界，未实现阶段 5 的正式发布和全量恢复清理。前端任务卡和正式产物下载仍属于阶段 6，当前通过会话快照、调度状态接口、事件和失败原因提供验收入口。
