# 第七阶段部署配置说明

本说明面向部署运维：配置的唯一目标是让账号、任务、产物和记忆在服务重启或容器重建后仍能恢复，同时让一个部署内的所有用户共享明确的资源上限。

## 1. 持久目录

| 含义 | 环境变量 | Docker 默认值 | 保存内容 |
|---|---|---|---|
| 应用持久根 | `GTAI_DATA_ROOT` | `/app/data` | 账号注册表、JWT 密钥、对话、研究区、用户设置、记忆、SQLite 台账和执行清单 |
| 项目数据根 | `WORKSPACE_ROOT` | `/app/data/users` | 各用户项目中的大体量栅格、中间表和结果视图；可单独挂载大容量盘 |
| 临时目录 | `GTAI_TEMP_ROOT` | `/app/data/tmp` | 临时文件；纳入部署磁盘规划，不代表正式产物 |
| 状态数据库 | `GTAI_STATE_DB` | `${GTAI_DATA_ROOT}/state_kernel/ledger.sqlite3` | 任务、运行、节点、尝试、事件、产物和记忆写回待办 |

程序启动时会创建目录并执行真实写入探针。SQLite 路径若位于 UNC、Windows 映射网络盘、NFS、CIFS、9p 等网络文件系统，服务会拒绝启动。项目数据根可以位于另一块盘，但不能据此把 SQLite 搬到共享网络目录。

如果只修改 `GTAI_DATA_ROOT`，程序会从仓库旧 `data` 目录补拷账号与控制元数据，已存在的新文件不会被覆盖，大型 `workspace` 栅格不会自动复制。旧项目记录中的绝对路径仍保留；确需搬动大文件时应由管理员显式迁移并核对路径。

## 2. Docker 持久化

最小可靠启动方式如下：

```bash
docker volume create geothermoai_data
docker run -d --name geothermoai -p 7860:7860 \
  --memory=16g --cpus=16 \
  -v geothermoai_data:/app/data \
  geothermoai-image
```

大文件项目盘分离示例：

```bash
docker run -d --name geothermoai -p 7860:7860 \
  --memory=16g --cpus=16 \
  -v geothermoai_data:/app/data \
  -v /srv/geothermoai-projects:/projects \
  -e WORKSPACE_ROOT=/projects \
  geothermoai-image
```

删除并重新创建容器时必须再次挂载相同数据卷。仅使用 Dockerfile 中的 `VOLUME` 声明而不固定卷名，会产生匿名卷，不便于确定地恢复原部署。

## 3. 调度资源预算

所有账号、项目和对话共享同一套部署预算，不会为每个用户各复制一份额度。

| 配置项 | 环境变量 | 默认值 | 说明 |
|---|---|---:|---|
| 计算作业数 | `GTAI_COMPUTE_JOBS` | 1 | 同时运行的重计算节点 |
| 下载作业数 | `GTAI_DOWNLOAD_JOBS` | 1 | 同时运行的下载节点 |
| 下载连接数 | `GTAI_DOWNLOAD_CONNECTIONS` | 8 | 全部署连接总数，不能小于下载作业数 |
| 预取包数 | `GTAI_PREFETCH_PACKAGES` | 1 | 允许的预取窗口 |
| 目录检索数 | `GTAI_CATALOG_JOBS` | 2 | STAC 等轻量目录请求并发 |
| 模型请求数 | `GTAI_MODEL_JOBS` | 2 | 外部模型调用并发 |
| CPU 预算 | `GTAI_CPU_BUDGET` | 自动探测 | 与容器配额、进程亲和性、主机值取最严格边界 |
| 内存 GiB | `GTAI_MEMORY_GIB` | 自动探测 | 与容器和主机上限取最严格边界，再保留百分之二十余量 |
| 磁盘紧急余量 GiB | `GTAI_DISK_MARGIN_GIB` | 自动探测 | 低于余量时停止新派发 |
| 磁盘缓存 GiB | `GTAI_DISK_CACHE_GIB` | 20 | 下载与执行缓存预算，不超过可见磁盘的百分之十 |
| 节点超时秒 | `GTAI_NODE_TIMEOUT_SECONDS` | 7200 | 单节点运行时间上限 |
| 网络尝试次数 | `GTAI_NETWORK_ATTEMPTS` | 3 | 下载类节点的有限尝试次数 |

所有数值必须是有限正数；作业数、连接数、预取数和尝试次数必须是正整数。配置错误不会回退到隐藏默认值，而是在启动时明确报错。

## 4. 记忆和缓存

| 配置项 | 环境变量 | 默认值 | 说明 |
|---|---|---:|---|
| 用户运行时缓存容量 | `GTAI_USER_CACHE_CAPACITY` | 8 | Assistant、Agent 和记忆管理器最多缓存的用户数 |
| 用户缓存闲置秒数 | `GTAI_USER_CACHE_TTL_SECONDS` | 1800 | 超时后仅移除缓存引用，不破坏正在处理请求持有的对象 |
| 写回最大尝试数 | `GTAI_MEMORY_WRITEBACK_ATTEMPTS` | 4 | JSON 与向量目标分别计数，达到上限后失败留痕 |
| 写回退避起始秒 | `GTAI_MEMORY_WRITEBACK_BASE_SECONDS` | 2 | 后续按指数退避 |
| 写回轮询秒 | `GTAI_MEMORY_WRITEBACK_POLL_SECONDS` | 1 | 独立写回执行器轮询周期 |
| 检索缓存条目数 | `GTAI_SEARCH_CACHE_ENTRIES` | 64 | Data Space 搜索缓存的 LRU 容量 |
| 检索缓存闲置秒数 | `GTAI_SEARCH_CACHE_TTL_SECONDS` | 600 | 到期条目会从内存真实删除 |

实验 JSON、实验向量、成功工作流 JSON、成功工作流向量是四个独立待办。某一路失败不会把已经完成的科学运行改成失败，也不会删除正式产物；任务日志会显示“结果已生成，经验保存待重试”。完整流程只有同时存在评价结果且测试集 R² 不低于 0.75 时，才会进入可复用成功工作流。

## 5. 配置优先级与示例

环境变量优先于 `config/deployment.json`，文件中的空路径表示采用程序默认值。示例：

```bash
docker run -d --name geothermoai -p 7860:7860 \
  --memory=16g --cpus=16 \
  -v geothermoai_data:/app/data \
  -e GTAI_COMPUTE_JOBS=1 \
  -e GTAI_DOWNLOAD_CONNECTIONS=8 \
  -e GTAI_MEMORY_GIB=16 \
  -e GTAI_DISK_CACHE_GIB=20 \
  geothermoai-image
```

部署日志会输出解析后的持久路径和最终有效预算，便于确认容器限制是否真实生效。`config/deployment.json` 中带有同义中文说明，可作为版本化默认配置使用。
