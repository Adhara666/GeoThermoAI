# GeoThermoAI 记忆系统实际架构

> 依据 `GeoThermoAI_新数据下载_docker` 当前代码梳理（2026-08-06）。
> 记忆系统采用**结构化 JSON + 向量 RAG 混合存储**：精确查询走 `experiments.json`，语义检索走 ChromaDB，领域知识来自内置种子，嵌入优先 bge-small-zh-v1.5（ONNX）。

---

## 1. 总体架构

```
┌────────────────────────── 前端 Vue3 ──────────────────────────┐
│  聊天/项目/对话（删除项目/对话时弹窗提示会清除实验记忆）          │
└──────────────────────────────┬───────────────────────────────┘
                               │ REST / SSE
┌────────────────────────── server.py ──────────────────────────┐
│  _memory_for()        每用户懒加载 MemoryManager（按 uid 缓存） │
│  process_command      conv_id / project_id / memory_manager    │
│  delete_project       → delete_project(project_id)            │
│  delete_conversation  → delete_conversation(project_id, cid)  │
└──────────────────────────────┬───────────────────────────────┘
                               │
┌────────────────────── GeoThermoAgent ─────────────────────────┐
│  咨询路径  context["memory"] = enrich_prompt(...)             │
│  计划路径  memory_block 注入 System Prompt                     │
│  _execute_plan  exp_state 聚合 → auto_save_experiment(...)    │
└──────────────────────────────┬───────────────────────────────┘
                               │
┌────────────────── core/memory/ ── MemoryManager ──────────────┐
│  ├─ RAGStore        ChromaDB 持久化（向量）                    │
│  │    ├─ global_knowledge  领域知识（全局）                    │
│  │    └─ project_{id}      项目历史经验（语义）                │
│  ├─ ExperimentLog   experiments.json（精确查询层）              │
│  ├─ Preferences     preferences.json（项目偏好键值）            │
│  ├─ seed_data       领域知识种子（K01–K31 子集）                │
│  └─ EmbeddingFunction  bge-small-zh-v1.5 ONNX 编码器           │
└───────────────────────────────────────────────────────────────┘
```

---

## 2. 存储结构

`memory_root = <项目根>/data/users/{uid}/memory`（`server._user_dir()/memory`，按用户隔离）。

```
data/users/{uid}/memory/
├── knowledge_seed.json            # 领域知识种子落盘（幂等播种，供审计）
├── chromadb/                      # ChromaDB PersistentClient 目录
│   ├── chroma.sqlite3
│   └── {collection_uuid}/         # 向量索引（global_knowledge 与各 project_{id}）
└── projects/{project_id}/         # 按项目稳定 id 隔离
    ├── experiments.json           # 结构化实验记录（数组 append，原子替换）
    └── preferences.json           # 项目偏好键值
```

- `project_id`：来自 `data/users/{uid}/conversations/_projects.json` 中项目的稳定 `id`。
- 对话级联删除依据：实验记录中的 `conv_id` 字段。

## 3. 模块清单与职责

| 模块 | 职责 |
|---|---|
| `core/memory/__init__.py` | 统一导出 `MemoryManager / RAGStore / EmbeddingFunction / ExperimentLog / Preferences / SEED_ITEMS` |
| `seed_data.py` | 领域知识种子 `SEED_ITEMS`（K01–K31 子集，18 条），`seed_document()` 组装 `knowledge_seed.json` |
| `rag_store.py` | ChromaDB 封装：collection 管理、`save_experience` / `save_knowledge`（幂等）、`search_for_agent` / `search_knowledge`、按 `source_conv` 删除、`EmbeddingFunction`（bge ONNX 优先） |
| `experiment_log.py` | `experiments.json` 精确查询层：追加（paused 覆盖）、按 conv 删除、`get_recent`、`get_best`（测试集 R² 最高） |
| `preferences.py` | `preferences.json` 键值读写（`get/set/all`，原子替换） |
| `memory_manager.py` | 聚合入口：`ensure_seeded` 播种、`auto_save_experiment` 双写、`enrich_prompt` 三段注入、`delete_conversation` / `delete_project` 级联、偏好读写 |

## 4. 核心数据流

### 4.1 初始化与播种（懒加载）

`server._memory_for()` 首次使用某用户时：

1. 构造 `MemoryManager(memory_root=data/users/{uid}/memory, embedding_model_dir=/app/models/bge-small-zh-v1.5)`；
2. `ensure_seeded()`（幂等）：
   - 写 `knowledge_seed.json`（已存在则不重写）；
   - `save_knowledge(SEED_ITEMS)` 灌入 ChromaDB `global_knowledge`（`count() > 0` 跳过）。
3. 实例缓存于 `server._user_memories`，进程内复用。

### 4.2 写入：实验自动入库

`_execute_plan`（geo_thermo_agent.py）执行各 Skill 时聚合 `exp_state`：

```
acq_params(region/日期) / pair(选中配对) / data_features
rf_data(test_metrics/feature_importance/params) / acc_data(closure)
step_success{} / failed(首个失败步骤) / paused
```

收尾判定：`paused`（等待用户）→ `failed`（首个失败步骤）→ `success`，然后 `_finalize_experiment(status)`：

1. `_build_experiment_record(status, failure_stage, failure_message)` 组装结构化记录（含 `experiment_id`、`conv_id`、`region`、`date_range`、`pair`、`status`、`timestamp`、`data_features`、`model/params/metrics/feature_importance/independent_prediction`、`closure`、失败信息）；
2. `memory_manager.auto_save_experiment(project_id, record)` 双写：
   - `experiments.json` 追加（同 `conv_id` 的 paused 记录先移除再追加 → 暂停后续跑完只留 success）；
   - `_record_to_paragraph(record)` 组自然语言段落 → `RAGStore.save_experience` 写入 ChromaDB `project_{id}`，metadata 带检索键：`source_exp / source_conv / region / model / r2 / date / status`。

### 4.3 读取：Prompt 注入

`process_command` 两条路径：

- **咨询路径**（问句/原理/推荐类）：`context["memory"] = memory_manager.enrich_prompt(project_id, user_input)` → `ask_stream`（注入为「当前软件状态」中的 memory 字段）。
- **计划路径**：`memory_block = enrich_prompt(...)` → 拼入 `_build_system_prompt` 的「领域知识」段；无记忆时回退 `_BASIC_KNOWLEDGE` 兜底。

`enrich_prompt(project_id, query, n=6)` 输出三段：

1. **领域知识参考**：`search_knowledge(query, n=8)`（检索空则 `_fallback_knowledge` 兜底精选种子）；
2. **当前项目历史经验**：`search_for_agent(project_id, query, n≤3)`；
3. **历史最佳实验**：`experiment_log(project_id).get_best()`（测试集 R² 最高的 success 记录，附参数 JSON）。

### 4.4 删除级联

- **删除对话**（`server.delete_conversation`）→ `memory_manager.delete_conversation(project_id, cid)`：
  - `experiments.json` 按 `conv_id` 删记录；
  - ChromaDB `project_{id}` 按 metadata `source_conv` 删条目。
- **删除项目**（`server.delete_project`）→ `memory_manager.delete_project(project_id)`：
  - 删 `memory/projects/{project_id}/` 目录；
  - 删 ChromaDB `project_{id}` Collection（`delete_project_collection`）。

失败仅 `logging.warning`，不影响删除主流程。

## 5. 嵌入模型（EmbeddingFunction）

- **候选目录**（依次尝试）：显式 `model_dir` → 环境变量 `BGE_MODEL_DIR` → 默认相对目录 `models/bge-small-zh-v1.5`（Docker 内 WORKDIR=/app 命中预下载模型）。
- 目录需含有效文件（`.onnx/.bin/.safetensors` 或 `tokenizer.json/config`），否则视为未配置跳过。
- **bge-small-zh-v1.5 ONNX**：`AutoTokenizer`（transformers，仅 tokenizer 无需 torch）+ `onnxruntime` CPU；均值池化 + L2 归一化，**512 维**。
- 查询编码自动加前缀「为这个句子生成表示以用于检索相关文章：」；文档编码不加。
- 模型缺失/加载失败 → 回退 ChromaDB 内置 ONNX（all-MiniLM-L6-v2，需联网下载）。
- 部署：Dockerfile 构建期经 `HF_ENDPOINT=https://hf-mirror.com` 预下载到 `/app/models/bge-small-zh-v1.5`。

## 6. 领域知识种子（seed_data.py，18 条）

| ID | 主题 | 用途 |
|---|---|---|
| K01 | TTRI 公式 | 系数拟合/复用/插值规则 |
| K02 | TCR 机制 | 以实际实现为准（block_constant 默认 / smooth_recentered 可选） |
| K03 | 降尺度原理 | 双阶段框架 + 互补动机 |
| K04 | MB 指标定义 | 精度指标口径 |
| K05 | 数据源 | Planetary Computer + Copernicus Data Space，不使用 GEE（国内可直连） |
| K06 | TTRI 解决的问题 | 地形变量跨分辨率失真、热效应空间插值 |
| K07 | TCR 解决的问题 | 跨尺度系统性偏差、三项设计机制 |
| K10 | Landsat 参数 | 波段/定标/QA |
| K11 | Sentinel-2 参数 | 波段/按景定标/SCL |
| K12 | DEM 数据源 | Copernicus GLO-30 |
| K13 | 影像配对规则 | 时间差 ≤ 2 天、云量阈值 |
| K20–K23 | 调参规则 | 样本量→n_estimators、地形→max_depth、温度变异→min_samples_leaf、植被→max_features |
| K24 | 指标解读基准 | 测试集 R² 分档 |
| K30 | 光谱指数公式 | NDVI/NDWI/NDBI |
| K31 | 地形特征计算 | Slope/Aspect 由 DEM 计算 |

播种幂等：种子内容变更后需删除已播种的 `knowledge_seed.json` 与 `global_knowledge` Collection 才会重新灌入新版本。

## 7. 与 Agent / Server 的集成点

| 位置 | 内容 |
|---|---|
| `server._memory_for()` | 每用户懒加载 + `ensure_seeded()`，缓存于 `_user_memories` |
| `server.process_command 调用`（chat 线程） | 传 `conv_id`、`project_id`、`memory_manager` |
| `geo_thermo_agent.process_command` | 咨询/计划两路径 `enrich_prompt` 注入 |
| `geo_thermo_agent._execute_plan` | `exp_state` 聚合 → `_finalize_experiment` 收尾入库 |
| `server.delete_conversation / delete_project` | 记忆级联删除 |
| 前端 Sidebar.vue | 删除项目/对话弹窗提示「清除实验记忆与历史经验」 |

## 8. 设计约定

1. **写失败不阻塞**：所有记忆写入/播种/删除失败仅告警，绝不抛给 Agent 主流程。
2. **多用户隔离**：`data/users/{uid}/`，assistant/agent/memory 均按用户独立实例。
3. **每项目隔离**：`projects/{project_id}/` + ChromaDB `project_{id}` Collection。
4. **paused 覆盖**：暂停后续跑完，`experiments.json` 同 conv 只留 success 记录。
5. **原子写**：JSON 通过 `core.atomic_io.atomic_write_json` 原子替换，避免半写文件。
6. **嵌入降级链**：bge ONNX → ChromaDB 内置，保证零配置可用。
7. **实验记录口径**：`closure` 为粗尺度闭合（不含 5K 时代字段），指标明确区分 train/test。
